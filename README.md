
# TOPSTER 리팩토링

## TOPSTER란

앨범 커버 이미지를 모아서 원하는 주제(연간 결산, 인생 앨범 등)로 콜라주를 만드는 웹 도구.
Last.fm에서 앨범을 검색해 그리드에 배치하고 이미지로 저장하는 게 핵심 기능.

## 만들게 된 배경

JS를 막 배우기 시작한 시점에 만든 프로젝트. 선생님이 "포트폴리오에 프레임워크 없이 바닐라 JS로 만든 것도 하나 넣어보라"고 조언해주셨음 — 프레임워크에 기대지 않고도 언어 자체에 대한 기본기가 있다는 걸 보여주기 위해서. 그 말을 듣고 기본기 있어 보이고 싶어서 의욕적으로 만든 프로젝트였는데, 다시 열어보니 위에 나열한 것처럼 허점이 많은 상태였음. 처음 배운 사람이 만든 것치고는 동작은 했지만, 그 이후로 실력이 늘면서 다시 보니 손볼 곳이 한둘이 아니었던 셈.

## 왜 문제라고 생각했나 / 왜 바꿀 필요를 느꼈나

원본은 바닐라 HTML/CSS/JS로 짠 프로젝트였는데, 아래 이유로 그대로 두기 어렵다고 판단함.

### 버그

1. `index.js` 108번 줄 — 검색결과 렌더링 시 `<img>` 태그에 닫는 `>`가 없음.
   `<img id="album_img" src=${...}` 로 끝나고 바로 `</li>`. 브라우저가 알아서 보정해서 화면엔 안 티나지만 명백한 오타이고, 이런 게 하나 있으면 다른 곳도 의심하게 됨.

2. HTML의 `ondrop="drop(event)"`, `ondragover="dragEnter(event)"` — `drop`, `dragEnter` 함수 자체가 어디에도 정의 안 돼있음.
   실제 드래그앤드롭은 Sortable.js 라이브러리가 처리해서 에러는 안 나지만, 코드만 읽으면 있지도 않은 함수를 호출하는 죽은 참조로 남아있는 상태.

3. `getAlbum()` 안에서 `title = searchInput.value` — `let`/`const` 없이 대입, 암묵적 전역 변수 생성.
   non-strict script라 에러는 안 나지만, 다른 곳에서 `title`이라는 이름을 또 쓰면 충돌날 수 있는 나쁜 습관.

4. `id="chk"`가 라디오 버튼 5개에 전부 중복 — HTML 스펙 위반. `label for="chk"`는 사실상 첫 번째 라디오만 가리키고 나머지 4개는 라벨 클릭으로 선택 안 됨.

5. 검색결과 `<li><img id="album_img">`도 결과 개수만큼 중복 id 생성 — 역시 스펙 위반. `getElementById`로 뭔가 찾으려 하면 항상 첫 번째 것만 잡힘.

### 미완성 / dead code

6. `cellNumHandle()` — 그리드 셀 크기 조절 기능이 미완성 상태로 방치돼있었음. 변수만 선언하고 실제 이벤트 처리나 렌더링 로직이 하나도 없음. CSS에 `.frame_num` 클래스가 정의돼있는데 정작 HTML엔 해당 요소가 없어서, 애초에 만들다 만 흔적만 남은 상태.

7. `frameColor()`, `getAlbum()` 함수 안에 주석 처리된 구버전 코드 블록이 그대로 남아있음. 어느 게 실제로 쓰이는 로직인지 코드만 봐선 헷갈림.

### 구조/보안

8. Last.fm API 키(`7108708792074ac473a8d262368a6c78`)가 클라이언트 코드에 그대로 하드코딩되어 깃허브에 공개돼있었음.

9. 전역 함수/변수를 나열하는 구조 — 상태 관리 없이 DOM을 직접 조작(`querySelector` + `innerHTML`)하는 방식이라, 그리드 사이즈나 컬러 같은 상태가 바뀔 때마다 관련된 모든 DOM을 수동으로 다시 그려줘야 함. 기능 하나 추가하려면 서로 안 얽혀야 할 함수들까지 손대야 하는 구조였음.

### Figma 재디자인에서 새로 생긴 요구사항

10. 프레임(그리드 테두리) 색상 선택 — 라디오버튼 5색 고정 방식으로는 새 디자인의 자유로운 색상 선택을 못 받아서 구조 자체를 바꿔야 했음.
11. 그리드 사이즈 — 기존엔 4×4 고정이었는데 새 디자인은 사용자가 입력해서 가변으로 조절해야 함. 위 6번에서 미완성으로 남아있던 기능을 이번에 실제로 완성해야 하는 상황.

이 열한 가지가 겹쳐서 버그 몇 개만 패치하는 걸로는 안 되고, Vue로 구조 자체를 다시 짜는 쪽으로 결정함.

## 왜 Vue로 갔나

회사에서 써본 경험이 있는 게 가장 큰 이유. 거기에 솔직히 말하면 기술스택을 좀 화려하게 보이고 싶은 마음도 있었음.

## 뭘 바꿨나 (극복한 점)

- 바닐라 JS → Vue 3 + Vite로 전환. 상태(제목, 검색결과, 그리드, 컬러)를 반응형으로 관리해서 기능 추가/수정이 한 곳에서 끝나게 함.
- 위에서 지적한 버그(중복 id, 끊긴 참조, 암묵적 전역 변수, 닫히지 않은 태그) 전부 제거.
- 미완성이던 그리드 사이즈 조절 기능을 실제로 동작하게 구현.
- 컬러 선택을 라디오버튼(5색 고정)에서 네이티브 컬러피커(전체 스펙트럼)로 교체.
- 검색결과 렌더링을 CSS Grid+aspect-ratio 방식에서 고정 픽셀 flexbox로 바꿔서 레이아웃이 이미지 로드 실패 시에도 깨지지 않게 함. 이미지 로드 실패 시 브라우저 기본 깨진 아이콘 대신 플레이스홀더로 대체.
- Figma 리디자인 반영 (좌우 2단 레이아웃).

## 기능 설명

1. **타이틀 입력** — 입력 후 Enter를 누르면 캡처 영역 상단 제목이 바뀜.
2. **앨범 검색** — 아티스트명/앨범명 입력 후 검색하면 Last.fm에서 결과를 가져와 리스트로 보여줌.
3. **그리드에 앨범 삽입** — 검색결과를 클릭하면 첫 번째 빈 칸에 자동으로 들어가고, 드래그해서 원하는 칸에 직접 놓을 수도 있음.
4. **그리드 내 위치 이동** — 이미 넣은 앨범을 드래그하면 다른 칸이랑 자리가 바뀜(스왑).
5. **그리드에서 빼기** — 채워진 칸을 더블클릭하면 앨범이 빠지고 다시 빈 칸이 됨.
6. **그리드 사이즈 조절** — 열/행 개수를 +/- 버튼으로 각각 조절 (1~8칸).
7. **컬러 선택** — 컬러피커로 캡처 영역 배경 및 그리드 칸 사이 간격 색을 자유롭게 지정. 기본값은 검정.
8. **다운로드** — 캡처 영역을 PNG 이미지로 저장.
